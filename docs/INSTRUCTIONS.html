Reviewer walkthrough

A guide to reviewing this repository: Playwright + TypeScript automation for the signup and login flows of a configured website, as a demonstration of an honest Auth0 test suite. Allow about 30 minutes for a full walkthrough, or 10 for a quick look.

1. Quick start (5 minutes)

Needs Node.js 22+ (the version CI uses) and network access to the site you test. Set TARGET_APP_URL and TARGET_SSO_URL in .env (see .env.example); no account is required for the public-page tests. The framework was prepared and verified on macOS only; on Windows use WSL or Git Bash. A fuller setup guide for new contributors is in docs/ONBOARDING.md.

git clone https://github.com/kengsenghor/playwright-auth-flows-demo.git playwright-auth-flows-demo
cd playwright-auth-flows-demo
npm ci
npx playwright install --with-deps chromium
npm run typecheck
npm test            # chromium only

Then open the report with npm run report.

The suite runs against the live production site. Run it once, not in a loop or with --repeat-each: repeated automated logins trigger the site's captcha, which then makes some tests skip (see below). Wait a while if that happens.

2. What you will see, and why

16 tests. With a fresh clone (no .env, no saved session) the expected result is about 11–13 passed, 3–5 skipped, 0 failed. Skips are deliberate; each reports its reason, and the run ends with a summary that lists them.

TestFresh cloneWhy
AF-LOGIN-01, 02, 06, AF-SIGNUP-01, 02, 03×4, 04, 05runsPublic pages, no account needed. 11 tests. AF-SIGNUP-04 checks that an unticked terms box is rejected.
AF-LOGIN-03 valid loginskippedNeeds a saved login session (.auth/user.json), created once by a person. See “Optional” below.
AF-LOGIN-04 ×2 invalid credentialsruns or skippedSkips if the site shows a captcha instead of the password step.
AF-LOGIN-05 wrong passwordskippedNeeds AUTH_TEST_USERNAME / AUTH_TEST_PASSWORD, and skips on a captcha.
AF-SIGNUP-06 live signupskippedOpt-in: it submits a real signup. Needs RUN_LIVE_SIGNUP=1 and SIGNUP_BASE_EMAIL.

A skip means not verified, not passed. The README says the same. An occasional timeout failure can also come from the live site (the SSO redirect and a third-party stylesheet were observed to stall); the page objects retry navigation, which reduced but did not remove this.

Optional: see the full set run

  • Valid login (AF-LOGIN-03): run npm run auth:save, log in by hand in the browser that opens (solve the captcha yourself), close it, then npx playwright test login-session --project=chromium. This needs an account you own on the site under test.
  • Manual-assist mode: with credentials in .env (copy .env.example), npm run test:login:manual opens a headed browser and pauses at a captcha so you can solve it, then the test continues and really checks the credentials.

5. Command cheat-sheet

npm test                    # all specs, chromium
npm run test:login          # login specs
npm run test:signup         # signup specs
npm run test:headed         # watch it run
npm run test:login:manual   # local, headed: pause at the captcha so a person can solve it
npm run auth:save           # one-time: save a login session to .auth/user.json
npm run typecheck           # TypeScript check
npm run report              # open the last HTML report

6. Cautions

  • Live site. Results depend on the site's availability. Avoid repeat loops against production.
  • Live signup creates a real account request and sends real email. It is off by default.
  • .auth/user.json contains live tokens. It is git-ignored; never commit or share it. .env is git-ignored too.
  • Publishing the report to GitHub Pages is disabled for now (private repo). To read a CI report: Actions tab → the run → Summary page → Playwright report (one HTML file) → Open. Traces, screenshots and videos are removed from that copy and secrets are redacted; the full report is the playwright-chromium artifact at the bottom of the same page.
  • The GitHub Actions workflow runs the tests only on manual dispatch; pushes run the typecheck only.
  • Do not run the manual-assist mode in CI: it needs a person at the browser.
The README is the source of truth if anything here drifts.
